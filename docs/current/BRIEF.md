# BRIEF — markdown-viewer

> 버전: v0.1 · 작성일: 2026-09-07
>
> 이 문서는 첫 버전에서 무엇을 왜 원하는지만 담는다.

---

## 1. 배경

로컬 폴더에 쌓인 문서를 빠르게 찾아 읽는 도구를 쓰고 있다. `markdown_browser`가
그 일을 해왔고 v0.2까지 왔다. 루트 폴더를 열어 탐색기에서 문서를 고르고, 탭으로
열어 GitHub Flavored Markdown으로 읽는다. 텍스트·코드 파일은 문법 강조와 복사
버튼이 붙은 읽기 전용 뷰어로 본다. 문서 안의 상대경로 이미지와 다른 문서로의
링크를 따라갈 수 있고, 세 테마·집중 보기·읽기 영역 글꼴 크기 조절·상태 표시줄의
경로 표시를 갖췄다.

그런데 그 앱은 문서를 읽는 기능과 앱의 껍데기를 한 덩어리로 갖고 있다. 창, 탐색기,
탭 줄, 상태 표시줄을 스스로 다 구현했고, 그래서 렌더링을 손보는 일과 탐색기·탭
조작을 손보는 일이 같은 코드 안에서 섞였다. v0.3에서 하려던 것 — 이미지 한 장
보기, 서로 다른 폴더의 동명 문서를 각각의 탭으로 구분해 열기, Jupyter Notebook
읽기, 빠진 단축키와 tooltip 채우기 — 도 의도만 적힌 채 멈췄다.

그 껍데기는 이제 따로 있다. 창·탐색기 트리·탭 줄·좌우 가르기·상태 표시줄·테마·
집중 보기·루트 경계·설정 보존은 완성된 상태로 주어지고, 앱이 채울 자리는 **트리가
무엇을 보여주는가**, **행을 고르면 무엇이 열리는가**, **탭 안에 무엇이 그려지는가**
셋이다. 이 프로젝트가 만드는 것은 그 셋 — 즉 문서를 읽는 부분이다.

`markdown_browser`는 2026-09-06에 `_archive\260813_markdown_browser\`로 동결했다.
이 프로젝트는 그것을 이어서 고치지 않고, 동결본이 도달한 열람 경험을 새 껍데기
위에 다시 얹는다. 동결본은 기준선이자 참고 자료로만 본다.

### 이 뷰어가 무엇인가

프로젝트 폴더와 문서 폴더의 마크다운을 빠르게 찾아 읽는 **읽기 전용 뷰어**다.
편집기도 아니고 범용 파일 관리자도 아니다. 원본 파일을 고치지 않고, 인터넷 없이
동작하며, 사용자가 고른 루트 폴더 밖으로는 나가지 않는다.

---

## 2. 이번 버전에서 풀고 싶은 문제

**동결본이 읽던 것을 그대로 읽고 싶다.** 마크다운·텍스트·코드가 같은 품질로
렌더링되고, 문법 강조와 복사 버튼, 상대경로 이미지와 문서 링크가 같게 동작해야
한다. 이번 버전이 동결본보다 못 읽는 상태로 끝나면 만들 이유가 없다.

**읽는 화면이 껍데기와 따로 손봬졌으면 한다.** 렌더링 방식이나 지원 형식을 고칠 때
탐색기·탭 코드를 건드리지 않고, 반대로 껍데기가 좋아질 때 이 앱이 그걸 그대로
받았으면 한다.

**가벼움과 빠른 실행을 잃지 않고 싶다.** 새 형식을 지원한다고 폴더를 열 때 파일을
미리 훑거나 무거운 실행 환경을 준비하지 않는다. 사용자가 고른 파일 하나만 그때
읽는다.

---

## 3. 하지 않을 것

- **껍데기를 다시 만들지 않는다.** 창 구성, 탐색기 트리의 조작, 탭 열기·닫기·이동,
  좌우 가르기, 메뉴 줄과 상태 표시줄, 테마 전환, 집중 보기, 루트 경계, 설정 보존은
  이미 갖춰진 것을 그대로 쓰고 이 프로젝트에서 다시 설계하지 않는다.
- **동결본이 구현하지 못한 것을 이번에 만들지 않는다.** 이번 버전에 새로 만드는 것은
  동결본이 실제로 구현해 둔 열람 기능까지다. 동결본 v0.3에서 의도만 적고 멈춘 것 중
  이미지 한 장 보기와 Jupyter Notebook 읽기는 다음 버전으로 미룬다.
  (서로 다른 폴더의 동명 문서를 각각의 탭으로 여는 것은 껍데기가 이미 해결한
  것이라 이 프로젝트가 만들 것이 아니다.)
- **편집 기능을 넣지 않는다.** 문서 수정·생성·삭제·이름 변경을 하지 않는다.
- **Mermaid·수식(KaTeX)·Obsidian Wiki Link·문서 전문 검색을 넣지 않는다.**
  동결본에서 후보로만 남아 있던 것들이고 이번 버전의 목표가 아니다.
- **파일 시스템 변경 자동 감시를 하지 않는다.** 외부에서 바뀐 내용은 사용자가
  새로 읽기를 실행했을 때만 반영한다.
- **열린 탭의 복원을 하지 않는다.** 앱을 껐다 켰을 때 마지막에 열려 있던 문서
  목록을 되살리지 않는다.
- **범용 파일 관리·git·터미널 실행을 넣지 않는다.**
- **설치 프로그램 제작·코드 서명·clean 환경 배포 검증을 하지 않는다.**
- **Windows 외의 운영체제, 모바일, 클라우드 배포를 고려하지 않는다.**

## 4. 완료 조건

> **읽는 것이 동결본과 같다** — `.md` 문서에서 표·체크박스 목록·인용문·코드 블록이
> GitHub Flavored Markdown으로 렌더링되고, 코드 블록과 코드 뷰어에서 Python · C++ ·
> TypeScript · JavaScript · JSON · PowerShell · YAML · TOML · Bash 아홉 가지 문법
> 강조가 적용되며, 복사 버튼이 현재 내용을 클립보드에 넣는다.
>
> **동결본이 열던 확장자를 모두 연다** — 아래 표의 확장자가 탐색기에 표시되고 탭으로
> 열린다. 표에 없는 확장자는 표시하지 않는다.
>
> | 구분 | 지원 확장자 |
> | --- | --- |
> | 마크다운 | `.md` |
> | 텍스트 | `.txt`, `.log` |
> | 코드 | `.py`, `.pyi`, `.cpp`, `.cc`, `.cxx`, `.h`, `.hpp`, `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.ps1`, `.psm1`, `.psd1`, `.sh`, `.bash` |
> | 설정 | `.json`, `.jsonc`, `.yml`, `.yaml`, `.toml` |
>
> 이미지 파일은 탐색기에 표시하지 않는다. 마크다운 문서 안에서 참조될 때만 보인다.
>
> **상대경로 참조가 따라가진다** — 루트 폴더 안의 상대경로 이미지 여섯 형식이 문서와
> 함께 표시되고, 루트 안의 상대경로 `.md` 링크는 앱 안에서 열린다(이미 열려 있으면
> 그 탭으로 간다). 대상이 없거나 루트 밖을 가리키면 대체 텍스트와 오류 상태를 보이고
> 앱은 계속 동작한다. 외부 URL은 기본 브라우저로 연다.
>
> **읽는 화면이 껍데기와 갈려 있다** — 지원 형식과 렌더링을 바꾸는 작업에서 껍데기
> 코드 수정이 0줄이다.
>
> **읽기 영역이 테마를 따른다** — 마크다운 본문·코드 블록·코드 뷰어·이미지 배경이
> 세 테마 각각에서 일관된 읽기 스타일로 보이고, 문법 강조는 밝은 테마에서 GitHub
> Light 계열, 어두운 테마에서 GitHub Dark 계열을 쓴다.
>
> **읽기 영역 글꼴 크기를 조절할 수 있다** — 마크다운 본문·텍스트 뷰어·코드 뷰어·
> 코드 블록의 글꼴 크기가 확대·축소·기본값 복원되고, 탐색기·탭·메뉴 줄·상태 표시줄의
> 글꼴 크기는 따라 바뀌지 않는다.
>
> **위험한 파일에서 멈추지 않는다** — 크기 상한을 넘는 파일은 열지 않고 이유를 표시하며,
> 바이너리 징후가 있는 파일과 지원하지 않는 인코딩은 오류 상태로 안내한다. 어느
> 경우에도 앱이 멈추거나 응답 없음 상태가 되지 않는다.
>
> **읽기만 한다** — 앱을 켜고 문서를 여닫고 끄는 동안 루트 폴더 안 파일의 내용과
> 수정 시각이 하나도 바뀌지 않는다.
>
> **가볍게 뜬다** — 앱 실행부터 탐색기가 보일 때까지 3초 이내, 1MB 마크다운 문서를
> 골라 화면에 렌더링될 때까지 1초 이내다(로컬 SSD 기준).
