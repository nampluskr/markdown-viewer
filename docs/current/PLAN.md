# PLAN — markdown-viewer

> 버전: v0.1 · 작성일: 2026-09-07
>
> 이 문서는 Phase 인덱스다. 상세 설계는 여기 쓰지 않으며, task 분해는 `backlog.json`이
> 담는다. 각 Phase의 완료 조건은 `SPEC.md`의 판정 방법으로 판정한다.

**모든 Phase에 공통으로 걸리는 조건이 둘 있다.** 하나, Phase를 닫을 때 앱을 실제로
띄워 더한 것이 화면에서 보이는지 사람이 확인한다. 둘, `shell/`과 `shared/design/`의
변경 줄 수가 0이다(NFR-4). 아래 각 Phase의 완료 조건에는 이 둘을 다시 적지 않는다.

---

## Phase 1. 껍데기 반입과 앱 골격

**목적** — 템플릿을 복사해 Electron 갈래만 남기고, 이 앱의 프리셋 자리를 만든다.

**대응 요구 ID** — NFR-3 · NFR-4 · 제약 2 · 제약 3 · 제약 5

**완료 조건**

* 저장소에 `shell/` · `shared/design/` · `presets/` · `host_electron/` · `vendor/`가
  있고 `host_pywebview/`가 0건이다.
* `presets/markdown/`이 활성 프리셋으로 지정돼 있고, 템플릿의 `presets/file` ·
  `presets/folder`와 참조 구현이 저장소에 남아 있지 않다.
* 저장소에 빌드 산출물을 만드는 단계가 0건이다.
* 앱이 창으로 뜨고 루트 폴더를 열면 트리가 보인다(껍데기 기능만으로).
* 저장소를 새로 받은 상태에서 실행 안내 문서의 명령만으로 앱이 뜬다.

---

## Phase 2. 문서 열기 경로

**목적** — 트리에 무엇을 보여주고 행을 고르면 무엇이 열리는지를 프리셋 안에서 정한다.
이 Phase 끝에 문서가 탭으로 열린다(내용은 원문 그대로여도 된다).

**대응 요구 ID** — FR-1 · FR-2 · NFR-2

**완료 조건**

* `SPEC.md` FR-1 표의 확장자만 트리에 보이고, 이미지와 그 밖의 확장자가 0건이다.
  대문자 확장자도 표시된다.
* `.md`와 그 밖의 지원 확장자가 서로 다른 보기로 열리고, 폴더 행은 탭을 열지 않는다.
* 껍데기 코드에 확장자 문자열이 나타나는 곳이 0건이다.
* 트리를 펼치는 동안 문서 읽기 호출이 0건이다.

---

## Phase 3. 마크다운 렌더링과 읽기 스타일

**목적** — 라이브러리를 반입해 GFM을 그리고, 읽기 영역이 세 테마를 따르게 한다.

**대응 요구 ID** — FR-3 · FR-4 · FR-12 · NFR-3 · NFR-5

**완료 조건**

* 표·체크박스 목록·인용문·코드 펜스·수평선·인라인 코드·링크를 담은 시험 문서의 모든
  요소가 해당 HTML 요소로 나타난다.
* 세 테마에서 읽기 영역의 배경·글자가 함께 바뀌고, 토큰을 거치지 않은 색이 0건이며,
  본문 대비가 4.5:1 이상이다.
* `<script>` · 이벤트 속성 · `javascript:` 링크를 담은 시험 문서에서 셋 다 실행되지
  않는다.
* 반입한 라이브러리의 버전이 고정돼 문서에 적혀 있고, 네트워크를 끊은 상태에서 위
  판정이 전건 통과한다.

---

## Phase 4. 텍스트·코드 뷰어와 문법 강조

**목적** — `.md`가 아닌 지원 파일을 읽는 보기를 만들고, 아홉 언어의 강조와 복사
버튼을 붙인다.

**대응 요구 ID** — FR-5 · FR-6 · FR-7 · NFR-6

**완료 조건**

* 줄 번호가 원문 줄 수와 같고, 아홉 언어 각각에서 토큰 색이 둘 이상 나타난다.
  언어 표시가 없거나 지원하지 않는 언어에서 원문이 오류 없이 보인다.
* 복사 버튼이 원문과 같은 내용을 클립보드에 넣고(줄바꿈 포함), 접근이 거부되면 실패가
  표시된다.
* 2MB 초과 파일 · 널 바이트를 담은 파일 · UTF-16 파일이 서로 구분되는 사유로 거절되며,
  세 경우 모두 앱이 멈추지 않고 다른 탭이 그대로 돈다.
* 위 오류가 오류 계약의 코드로 돌아온다.

---

## Phase 5. 문서 안의 참조 — 이미지와 링크

**목적** — 문서가 가리키는 다른 자원을 규칙대로 따라가게 한다.

**대응 요구 ID** — FR-8 · FR-9 · NFR-6

**완료 조건**

* 여섯 이미지 형식이 모두 표시되고, 없는 파일과 루트 밖 참조가 대체 텍스트와 오류
  상태로 나타나며 문서의 나머지는 그대로 보인다.
* 열려 있지 않은 문서로의 `.md` 링크가 새 탭을 열고, 이미 열린 문서로의 링크는 탭 수를
  늘리지 않고 그 탭을 활성화한다.
* 외부 URL이 앱 안에서 열리지 않고 기본 브라우저로 넘어간다.
* 루트 밖 링크와 이미지가 `ROOT_ESCAPE`로 거부되고 앱이 계속 돈다.
* 보기 코드가 파일시스템 API를 직접 부르는 곳이 0건이다.

## Phase 6. 읽기 경험 마무리

**목적** — 글꼴 크기 조절과 탭 수명 동안의 상태 유지를 붙이고, 읽기 전용을 확인한다.

**대응 요구 ID** — FR-10 · FR-11 · FR-12

**완료 조건**

* `Ctrl` + `+`/`=` · `Ctrl` + `-` · `Ctrl` + 휠 · `Ctrl` + `0` 네 조작이 읽기 영역에만
  적용되고, 50%~250% 범위 밖으로 나가지 않는다.
* 조작 전후로 탐색기·탭·메뉴 줄·상태 표시줄의 글꼴 크기가 같다.
* 탭을 전환했다 돌아오거나 반대쪽 조각으로 옮겨도 스크롤 위치와 글꼴 크기가 유지되고
  문서를 다시 읽지 않는다. 탭을 닫을 때만 보기가 폐기된다.
* 앱을 켜고 문서를 여닫고 끈 뒤 루트 안 파일의 내용 해시와 수정 시각이 실행 전과 같다.

## Phase 7. 회귀 대조와 버전 마감

**목적** — 동결본과 나란히 놓고 못 읽게 된 것이 없는지 확인하고, 성능과 문서 규약을
판정해 버전을 닫는다.

**대응 요구 ID** — FR-1 ~ FR-12 · NFR-1 ~ NFR-6

**완료 조건**

* 동결본(`_archive\260813_markdown_browser\`)이 열던 확장자와 렌더링 요소를 같은 시험
  문서로 대조해, 이 앱에서 열리지 않거나 다르게 보이는 항목이 0건이다.
* 실행부터 탐색기 표시까지 3초 이내, 1MB 문서 렌더링 1초 이내를 다섯 번 측정한 중앙값이
  기준 이내다.
* 모든 FR과 NFR의 판정 결과가 `PROGRESS.md`에 기록된다.
* `DOC-SCHEMA.md` 9절의 초기화 검사 목록과 `backlog validate`가 전건 통과한다.
* `README.md`의 "어떻게 쓰는가"가 실제 실행 절차와 일치한다.
